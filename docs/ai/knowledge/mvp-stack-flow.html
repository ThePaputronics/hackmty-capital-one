SPEI Intent Guard MVP Stack Flow

This diagram shows the simplest functional backend path for the MVP: receive a transfer event, validate it, persist the context, score anomaly risk, and return a decision before confirmation.

API entry

FastAPI

Receives requests such as POST /events and POST /risk/evaluate.

→
Request contract

Pydantic

Validates request bodies and shapes the response models for predictable API behavior.

→
Persistence

SQLAlchemy + Postgres

Stores users, accounts, beneficiaries, events, transfers, anomaly scores, and decisions.

Risk logic

scikit-learn

Scores whether the transfer behavior looks unusual compared with the user baseline.

Output

Decision response

Returns allow, warn, or pause with plain reason codes.

Developer loop

uv + pytest + Ruff

Installs dependencies, runs tests, and keeps the Python code consistent during the hackathon.

MVP rule: keep the product path small. No Redis, no worker queues, no observability stack, no LLM agent runtime until the basic SPEI risk flow works end to end.

FastAPI

Expose the backend product as HTTP endpoints.

Pydantic

Reject malformed data before it reaches business logic.

SQLAlchemy

Read and write database records through Python models.

Postgres

Keep the event history and decision audit trail durable.

scikit-learn

Provide a lightweight anomaly score for the MVP.

pytest, Ruff, uv

Support fast validation, formatting, and dependency management.
